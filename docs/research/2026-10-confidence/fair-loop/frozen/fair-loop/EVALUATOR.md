# Fair-loop prospective independent evaluator

This is one small paired repair study on two previously unreplayed, historical CPython PR identities. It tests bounded module bug repair, neighboring invalid cases and preserved API behavior. It does not measure ambiguity intake, general autonomy, unseen knowledge or model ranking. Task design/calibration is not solving efficacy. Prior Tweed studies and their outcomes remain immutable.

Two arms use current source entrypoint `4758787015f05a95ea38896f57a462316b3d9d80` and one actual Opus-authored candidate, with identical approved doc-only common references. The candidate/research/controller authors do not see task identities, source, head solutions or private checks before entrypoint freeze. Actor policy contains no scripts, assets, tests or modern worked module examples. Solvers get authentic base module, license, clear contract and authored visible regression only. Ordinary conventional product-test edits/additions are allowed; independent owner checks and baseline projection are immutable. No byte-freeze for actor tests, file-length accuracy gate or protocol CLI certificate applies.

Each arm/task has one 300-second main attempt and at most one 180-second fresh-context continuation retaining its workspace, using the same actual Opus high route, tools and registered $3/$2 ceilings. One exclusive global provider lock permits at most one live provider model process across research, candidate/controller development, task main and continuation stages. No separate model critic is run. The deterministic independent Codex-owned evaluator supplies actual required-gap feedback. Forward every observed required behavior/negative/regression/scope/current-source failure via structured rows; never disclose owner source, reference patch or private tracebacks. Optional caveats and excluded full builds/live workflows do not trigger repair. Timeouts are classified from process, provider and tool receipts, rather than assumed environmental or product failures.

Continuation admission has exactly two alternatives: an observed required artifact gap, or a cleanly settled explicit runtime/provider deadline with observed actual Opus identity, qualified tool/source custody and no unknown process/cleanup, even if the artifact already passes. A deadline guard with timed_out=true, reaped process, actual retained assistant model and stable retained source qualifies as a known runtime deadline without inventing a provider time_limit terminal. The same single continuation budget applies to both arms. Preserve the main missing terminal as its original delivery gap; a recovered final pipeline requires a new valid terminal, current complete independent proof and accounted full history. Delivery recovery is not a product defect or causal production repair. Unknown identity, infrastructure or unsettled source/process does not authorize retry to agreement. First-stage grades remain retained. Candidate self-claims and missing provider terminals do not change observed artifact behavior. Unresolved infrastructure or identity blocks comparative promotion, not a separately observed artifact diagnostic.

`evaluate.py --workspace PATH --task-id ID` projects declared actor production into authentic base with fixed focused baseline and private owner API checks. Both execute in a bounded, network-denied OS sandbox. The task interpreter, native `_csv` support and actual local module SHA/origin are pinned and recorded. Target source and bytecode paths across all available shared Python3.9/3.13/3.14 runtimes are denied; tested Python public API code origins must be inside the projected local module/helpers, even with forged file labels. Local helpers and fixed native support remain allowed. Grades require all positive, negative, regression and visible baseline checks, declared production scope, and unchanged current source during execution. Failed sandbox/setup, unclassified imports or timeouts without full proof remain explicitly unknown and do not generate repair-admitting binding rows. A SyntaxError whose filename is bound inside current projected actor source is an observed required source-load failure; explicit foreign API origin rejection is an observed binding failure. No skipped owner cases qualify. Safe feedback contains required rows and scope/current/binding status only; execution logs are custody evidence, not a solver answer key.

The accepted historical head must pass every registered positive/negative/regression case and visible baseline; the genuine base must fail new behavior while its existing visible baseline passes. Deliberate partial/overbroad fixes must fail. Equivalent implementation representations and conventional actor test edits must pass. Installed-module substitution and forged code origin must be rejected. These are pre-inference evaluator controls, not added task identities. Existing product tests may legitimately change with a requirement; unrelated semantics remain protected by independent behavioral regression checks.

Promotion requires strictly more final independently observed full required artifact completions than the incumbent, with no loss of any incumbent final completion, no material negative/regression/scope weakness and no infra-affected comparison. All-complete and partial-final ties retain the incumbent. No manual preference, shorter prose, faster run or first-stage score overrides this rule. Causal production repairs are descriptive: identify a genuine first-stage required behavior defect, a changed primary module fixing its cause and final independent boundary checks. Scope-only cleanup, repeated proof and provider-delivery recovery are separate and never count as causal production repairs. Inspect final diffs for hardcoded fixture outputs and unrelated changes; do not retrospectively add scored requirements. Qualitative complexity review is descriptive and blind to arm labels. Timing, actual tool requests and usage are descriptive, with failures/denials included and missing telemetry labeled unknown; necessary proof is not waste by a count alone. This panel cannot establish a universal method advantage.

CSV uses the existing Xcode Python3.9.6 support because unchanged 2022 source imports `_csv.__version__`, removed in newer runtimes; configparser uses Python3.14.7. Runtime versions/dependency hashes differ by task but are identical across arms. Related fixed implementations may exist in pretraining or shared runtime dependencies. Target source/pyc denial and doc-only policy reduce direct recipe exposure; they do not establish unseen solving. Accepted CSV contract follows merged title/docs/head (iterator coercion); the original body proposing sequence rejection is retained verbatim as historical provenance. No complete CPython suite/build or unrelated PR diff is an obligation. Full PSF licenses accompany published original source.
