# Bounded reobservation during atomic publication

Python 3.14 CI at commit `08746ee` failed the eight-process parallel-capture test: one capture reported unknown workspace binding. Python 3.10, 3.12 and the research suite passed. The [failed run](https://github.com/e3-solutions/tweed/actions/runs/38443195245) remains preserved. Its logs omit individual capture records, so the exact low-level CI cause is inferred rather than conclusively traced.

An independent investigator reproduced a matching production race with real Git and two real `write_json_exclusive_atomic` publishers. Each writer created its actual regular staging file, linked the completed record and removed staging in its genuine cleanup. Scheduling hooks released that cleanup between Git enumeration and `lstat`. One disappearing file succeeded after the existing retry; two disappearing files returned unknown despite identical baseline and final source. Ordinary-source and staging-type refusal controls still passed. This diagnosis and test design preceded implementation of the correction.

Version **0.7.1** allows up to eight additional complete inventories only when a missing name is an exact **untracked** protocol atomic staging candidate under the actual non-symlink evidence anchor. Classification permits a retry, never skipping an unseen entry or presuming its old type. Surviving tracked files, symlinks, special files and malformed/outside-anchor names retain their existing behavior. Ordinary missing source has its independent single retry; staging churn cannot replenish that budget. Exhaustion remains unknown. Sustained publication beyond this bound has no unconditional success guarantee.

The same exact name predicate serves existing regular-output exclusion and retry classification, including filesystem casing aliases through parent identity. No report schema, new dependency, dispatch service, global lock or relaxed software-pass rule is added.

Eight new deterministic tests exercise two and eight real publishers, finite exhaustion, mixed ordinary/staging instability, tracked missing names, symlink/type/lookalike/outside-anchor boundaries and casing aliases. On the previous implementation, nine positive/policy subcases failed; refusal controls remained passing. On the corrected implementation, all eight tests and 36 existing related tests passed. Full source-bound tests and the three-version CI matrix remain separately reported from those focused controls.

The correction is outside all frozen model comparisons. It improves one source-observation failure mechanism; it does not establish greater model accuracy, continuous immutability or end-to-end autonomous task success. Unsupported retained scratch directories in the owner's original checkout are a separate issue and remain preserved; the correction does not hide them or broaden exclusions.
