This experiment demonstrated no better eligible entrypoint; it does not show that the paper's approach fails.

“Complete” requires qualified actual provider delivery and current independent required gates across required stages. “Artifact gates” are passing current positive/negative/baseline/scope checks on the retained final source, even when a required provider terminal is missing. No terminal.complete self-claim was added as an extra gate. All six final patches pass the selected artifact checks; three observed stage deadlines prevent stronger completion claims:

- Incumbent PR26 and branch B PR26 completed their main stages and all gates. Their reported conflicting old whole-PR test and excluded-feature caveats were preserved; the focused contract did not require those old expectations.
- Branch A PR26's main reached150.10s without a qualified terminal and changed a protected existing test file. Its44.48s qualified repair restored the file and retained passing behavior. The unknown main delivery still prevents whole-cell completion.
- Branch A PR45 completed its main in125.15s with all gates. Incumbent PR45 reached150.15s without a qualified terminal although the independent patch gates passed; no retry was manufactured for agreement.
- Branch B PR45's145.54s main was qualified and behavior passed, but it added a new nested test module outside the evaluator's permitted test locations. The module did not exist in the base. Its sole90.12s repair removed it and restored scope and passed final gates, then reached its deadline without a qualified terminal. The relocated root author-check helper changed the projected artifact patch; primary runtime source was unchanged during repair. This is scope correction, not evidence of a production bug repair.

The frozen evaluator protected existing baseline-test bytes and excepted new root tests/helpers, while rejecting other new nested test locations. A added meaningful coverage to an existing file; B added a new module in the product's normal nested test directory. Both are common engineering practices, but each violated this experiment's different scope rule. These artificial restrictions limit panel representativeness; the recorded failures were not rescored away. The earlier scheduling review and B's repair feedback used an inaccurate existing/protected-file shorthand. B's scope_restore_baseline_bytes mapping was empty because the module had no baseline file; the actor nevertheless removed it and relocated the checks. Final source inspection corrects the description, while the imprecise raw feedback and historical records remain unchanged. Raw first and repair outcomes, source/patch bindings, scope diffs, actual commands and independent owner/baseline receipts are in [typed evidence](evidence/) and [RESULTS.json](RESULTS.json).

The frozen PR26 test test_receipt_size_boundary_is_review_only explicitly expects an emitted line of RECEIPT_MAX_BYTES+1 (4097 bytes), contradicting the new 4096-byte line requirement. The full historical suite is therefore not all green; the passing artifact gates cover the selected focused contract only. Freezing independent owner oracles against outcome-driven changes does not imply that ordinary product-test expectations should remain immutable when accepted requirements change.

This was related implementation/reference exposure, not private owner-oracle leakage, and PR45 was not blind to a current solution recipe. The historical slice and fresh task identity claims therefore do not establish novel, unseen-problem solving efficacy.
