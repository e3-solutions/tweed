# Frozen focused-slice evaluator

Incumbent and all common reference/toolkit bytes are pinned to 4758787015f05a95ea38896f57a462316b3d9d80. Only SKILL.md differs among three arms. Candidate authors receive identical prior facts and never receive this task panel. All evaluation actors solve on fresh isolated base snapshots. No incumbent-versus-installed-0.8/old-0.6 improvement claim is permitted.

Selection tasks are actual closed Tweed PR26 receipt-byte boundary and PR45 compact run receipt slices. Reserved confirmation is actual closed PR18 failure-diagnostics slice. Human PR bodies, closed state and exact original base/head commit IDs are stored under oracles/pr-N/provenance.json. Existing study IDs20/23/31/32/34/35/37/39/40 are excluded; PR19 is also excluded as the same accepted head as20. PR43/44 were queried and are open, not selected. These are historical slices never previously used as solver tasks in located study dossiers; related mechanisms and published source can be familiar. PR45 archive-export-ignored baseline tests are restored byte-for-byte from the pinned original Git tree, not newly seeded defects.

Contract: Standard focused task, declared required positive behavior, meaningful negative behavior and unchanged public defaults. Entire PR, unrelated obligations and live providers are excluded. Required final independent Codex execution of the frozen owner checks, declared focused baseline checks, scope check and source-current check establishes scoped proof. Author check claims cannot substitute. No product CLI protocol certificate is required outside this task's contract. Completion does not depend on keywords or MCP/model/call counts.

API: evaluate.py --workspace PATH --task-id tweed-prNN. It reuses existing safe regular production projection, full scope_diff and macOS no-network sandbox. It restores original tests and overlays immutable private owner tests over a pinned base; never executes candidate test edits. It returns one JSON gate receipt plus raw owner diagnostics. Fields include passed, oracle_passed, required_behavior_passed, negative_boundaries_passed, scope_violations, source_current, setup_status and failed_requirements. Return codes0/1/2 mean complete/observed gap/unknown setup; missing results, timeout or unexecuted tests remain unknown. Exact required public command/output/data checks survive helper renames and equivalent valid code.

One150-second/USD1.5 Opus main call plus at most one90-second/USD1 repair call per cell, same actual qualified solver model/effort across arms. Forward ALL requirement failures, including full scope verdict and out-of-scope diff; do not disclose private test source or accepted reference. Repair occurs only for observed required gaps, not gratuitous edits. Keep immutable first and final outcomes; final recoverable completion is accepted. Setup/model availability is verified through the actual controlled execution route before dispatch; model metadata is observed from receipts, never inferred from requested labels.

Classification: current positive+negative+focused-baseline+scope proof passes => complete. Observed required behavior failure => failed/partial with exact requirement. Missing required execution, stale source or unresolved diagnostics => partial/unknown, never complete. Explicitly excluded live-provider caveats do not become required gaps. A setup timeout before product work is a setup failure/unknown product outcome; runtime unknown attribution remains unknown. Only a task with an explicit latency requirement may count observed product latency as that requirement failure. No selected task has an implied speed requirement.

Promotion rule fixed before design/solve calls: candidate final complete count must strictly exceed incumbent over the two selection tasks; no task that incumbent completes may regress, no final scope violation, no unresolved unknown case. Ties keep incumbent. If both candidates strictly beat incumbent, only a unique higher final-complete count can select a provisional winner; if they tie, keep incumbent and do not run confirmation. No tool/token reduction, style or manual preference breaks a completion tie. The registered overhead proxy is MCP request count, separate from the task-completion gate. Count actual model-requested tool_use blocks whose name starts mcp__cp_trial__ in retained Claude-stream assistant messages; deduplicate by tool_use.id, include failed/denied requests, and sum solve plus repair across both selection tasks. Exclude StructuredOutput, offline preflight, independent Codex grader and branch-design calls; report branch-design cost separately. Missing/invalid stream material or tool IDs makes overhead unknown and prevents promotion. Candidate count must be <= incumbent count + max(2,ceil(0.25*incumbent count)); otherwise no promotion. Record observed output tokens, elapsed time, provider/API durations, tool receipts and repair cost descriptively; unavailable usage is unknown, never zero. Scheduling/network latency alone does not establish efficiency. Avoidable repeated identical requests can be described from receipts; this count is only a registered overhead proxy, and necessary proof is not waste by count alone.

Only a provisional winner triggers reserved PR18 confirmation with incumbent and winner under the same budgets and unchanged evaluator. Both must be final complete with current independent proof and no scope failure; a candidate cannot be worse than incumbent. Any failure/unknown/tie without strict selection improvement retains incumbent. Do not add tasks, retry/select seeds, tune thresholds, weaken negatives or reuse solver outcomes to change this panel. Report this tiny local design experiment's limits; it is not a broad benchmark or productivity estimate.
