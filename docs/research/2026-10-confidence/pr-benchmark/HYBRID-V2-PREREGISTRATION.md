# Separate V2 mixed-provider replay

This prospective registration defines a new exploratory 48-assignment replay.
It preserves the invalid first mixed-provider block and the original 84-assignment
comparison. Results from these blocks must not be pooled. Historical outcomes
informed the infrastructure correction and the public-behavior oracle selection;
V2 is not a confirmatory replication of the original Confidence Protocol study.

The question is whether changing only the peer provider improves accepted
submissions or truthful completion at a fixed main provider. Four pairings use
Astra/Astra, Opus/Opus, Astra/Opus and Opus/Astra on the identical six historical
PR behavior tasks, twice each. The package remains CP0.6 at `9f3afa6`, identical
role instructions, corrected public oracles, source snapshots, visible checks,
production paths and schedule rules. PR35 and PR39 remain bounded slices.

The new treatment is a qualified transport and cleanup adapter: all coordinator and stage
paths are absolute before switching to the actor cwd. Each stage first starts
the actual confined MCP server, lists its seven operational tools and exercises
listing; readonly stages must reject a source write. Claude live initialization
must contain the connected server and required tools. Missing inventory is
unknown and ineligible. Astra has an offline declared inventory and actual local
startup/call evidence; its live wire inventory and response model identity are
not observed. Its three resource handlers remain disclosed. This does not
establish strict complete-harness tool parity. The V2-only process helper reaps
the direct child before escalating original-group cleanup; the old helper lost
timeout receipts on a reproduced macOS zombie-only process group. Real permission
failures still propagate. Execution children also receive an empty confined home
and per-stage scratch outside the actor checkout. This restores the advertised
baseline tests without giving children the authenticated client's home or secrets;
the authenticated parent client keeps its normal account. Source remains readonly
for peers. See `V2-TIMEOUT-QUALIFICATION.md` for failed and fixed
actual-call controls; no historical-task outcome was rewritten.

Fixed stages remain 90 seconds for proof design, 240 for implementation, 90 for
adversarial review and 120 for repair, within a 600-second aggregate deadline.
Startup and qualification count against that deadline. Concurrency remains two.
No model substitution, retrial, new task hint or extra terminal call is permitted.
Claude dollar guards differ from Codex accounting; this is a wall-window study,
not a token- or cost-matched study. Total dollars remain unknown whenever a
provider omits them. Known Claude subtotal is not total cost or subscription
charge. Combining providers distributes work over existing authorized routes;
it does not increase or pool either account's entitlement.

The full staged hosted qualification passed both cross pairings on a non-task
toy using the exact final wrapper, actual reads and tests, source-bound confidence
capture and independent final behavior checks. Its eight stages do not enter
the efficacy denominator. Earlier invalid setup and qualification attempts stay
preserved separately. The callback toy separately establishes that Codex can
call Claude and read its returned receipt; external staging alone would not
establish that capability.

Before historical-task launch, use `seal_hybrid_v2.py` to seal and publicly commit the new protocol,
wrapper, independent grader, complete queue, task/package materials, qualification
reports and exact grader controls. Require all six base-RED/head-GREEN controls,
the two previously accepted alternative representations and fail-closed deletion
and qualification controls. Synthetic provider metadata in those grader fixtures
must remain labeled synthetic, not real model observations. The public registration
records zero V2 task outcomes at seal and every governing file hash. Bare adapter
`prepare` is provisional; the final seal requires resolved independent review,
actual hosted pipeline qualification, all six actual callback baseline checks,
and unchanged complete queue and task/prompt/resource fields. It pins the new
runtime, process helper and V2 grader in addition to the frozen controller.

Keep all 48 assignments in the denominator. Infrastructure-invalid, interrupted,
unavailable or unstarted assignments remain visible; unknown oracle outcomes,
declarations and costs are not converted into observed failures or zero values.
Report accepted submissions separately from accepted plus terminal completion,
finished required peers and no required gaps. Proof-packet quality and correctness
beyond the executed acceptance oracle remain unassessed.

Use the immutable task-cluster analysis: six paired task clusters, both repeats
within each cluster, exact empirical bootstrap as descriptive uncertainty only.
Report peer-provider contrasts separately at each fixed main provider; no pooled
vendor ranking, general population claim or attribution of cross-block differences
to the protocol. Retain all malformed/time-limited/incomplete attempts. Process-group
cleanup does not contain children that detach with a new session, and successful
controls do not establish absolute artifact immutability or whole-application
preservation.
