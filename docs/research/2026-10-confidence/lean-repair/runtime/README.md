# Lean repair controller contract

This new controller imports unchanged claude-first runner/analyzer helpers and the hybrid V2 adapters. It does not resume or rewrite an old cohort. The lifecycle is deliberately controlled: one checked Haiku source discovery per task is shared by the two guidance arms, followed by Opus development, a separate fresh read-only Codex review, and one final Opus repair or verification stage. It does not establish complete Confidence Protocol release certification or free agent orchestration.

The roster is three fresh task IDs × original/revised guidance × one trial. `prepare` seals a seeded fixed order, task/base/head/oracle inputs, exact original historical guidance lineage, common current toolkit, revised full instruction tree, shared discovery artifacts, current scripts, CLI versions, Codex qualification/catalog/inventory and budgets. Previous replay task IDs are excluded. No retry or substitution is supported; run, cell and stage directories are exclusively created before work.

Budgets are 480 seconds/USD4 for development, 180 seconds for read-only review, and 300 seconds/USD3 for the final Opus stage. A shared 1100-second cell deadline clamps all stages, executed checks and grading. Offline transport/confinement/control preparation is outside this clock. Exact Opus is `claude-opus-5-5` at high effort; Codex requests `gpt-6-astra` medium and records requested-only attribution when actual model metadata is absent. Haiku requests `claude-haiku-5-5` medium, 120 seconds/USD0.6, empty native/MCP tools. The schema-only StructuredOutput mechanism may appear in initialization. The discovery packet uses base source only, with numbered lines and at most six quoted facts. Quote validation permits only omission of a sole terminal LF; the unconstrained explanatory `fact` string is not delivered to developers.

Development and closure use common controlled tools, current executable toolkit and the assigned full guidance tree. `request_review` returns explicitly unavailable during development; the independent review is scheduled outside that timer. Reviewer context receives task, normalized first candidate source, production diff and executed check/frozen-grade diagnostics; it has no arm, policy, `.protocol`, `.confidence`, source history, grader source or reference implementation. Original tests and acceptance fixture sources remain outside actor access. The final frozen behavioral grader is disclosed as feedback and is not an unseen post-repair holdout.

All owner checks and review witnesses execute on immutable baseline tests/dependencies with only candidate production overlaid. The frozen grader already restores this same trust boundary. Actor test/scratch changes cannot satisfy owner requirements. Review witnesses are self-contained inline Python.

Both arms receive identical disclosure rules: visible/required checks, frozen public-boundary grade diagnostics and independent findings. A blocking reviewer finding is resolved only by an actually failing bounded witness on the first source followed by a bound passing execution on the final source. Missing, unrun, timed-out or always-passing witnesses leave the finding unresolved. All proposed witnesses go through the existing readonly sandbox command envelope. No reviewer finding can be closed by developer prose.

The main stage may be recovered after timeout or missing terminal only when its model, tool inventory, process ownership and source provenance otherwise qualify. A missing receipt, mismatched model/tools, scope violation or unknown lifecycle is not recoverable. First-pass delivery is never retroactively promoted. Every complete review receives the one fixed final Opus stage; a correct candidate may verify with no edit. Reports distinguish actual patch repairs from no-change closure.

Final acceptance requires factual qualified final developer terminal with complete=true/empty remaining, qualified complete independent review, current final source/patch/grade/check binding, fixed behavioral acceptance, required checks passing and no unresolved blocking finding. Developer assertions do not prove coverage; the task manifest's executable required checks and frozen boundary assertions supply evidence. This remains scoped product success, not complete CP certification.

`analyze` re-parses saved actual provider streams and terminals, model/tool facts, local qualification and review JSON, checks artifact hashes, reconstructs first/final patches and source associations, re-derives check outcomes and witness resolution, and retains every assigned identity including never-started/started-unknown cells. It does not trust saved PASS booleans as proof. Lifecycle facts remain process receipts; original-process-group cleanup does not guarantee containment of detached setsid descendants. Costs are CLI metadata/guards, not invoices.

Config fields are `manifest`, `toolkit_directory`, `original_registration`, `codex_catalog`, `codex_qualification`, `discovery_receipts` keyed by task ID, `arms` mapping original/revised to `policy_directory`, `seed`, `aggregate_seconds:1100`, and `feedback_rule:executed_public_boundary_diagnostics_no_oracle_source`. `policy_checks` are rejected because protocol ledger certification is outside this scoped product loop. Task fields use the existing manifest contract, plus optional `required_checks` and `discovery_paths`.

Offline entry points are `controller.py prepare --config CONFIG --study NEW_STUDY`, `controller.py controls --study STUDY`, and `controller.py analyze --study STUDY`. Hosted discovery has its explicit entry point `discovery.py --manifest MANIFEST --task TASK --output NEW_OUTPUT`. Hosted cell inference is blocked until `activation.json` pins the private registration SHA and a committed public envelope. Activation fields are `registration_sha256`, `git_commit`, `public_registration_path` (repository relative), and `public_registration_sha256`. The committed public envelope must include `private_registration_sha256`; its full content can be sanitized for public review without exposing private paths. `controller.py run --study STUDY` then executes the sole fixed roster invocation.

Ten focused offline controls cover roster/no-retry/caps, missing review/source/check bindings, bounded main timeout recovery versus model/tool provenance mismatch, review/grade disagreement, executable witness fail→pass, missing actual reviewer terminal, raw Haiku stream/model/quote forgery, immutable test/scratch projection and missing raw command outputs. The forced CPU assertion failure→edit→final-grade loop uses simulated model invocations and is explicitly not an empirical model repair result.
