# Lean full repair-loop comparison

Registered before task-specific hosted discovery or implementation calls. The protocol candidate was authored by actual Opus 5.5 with one bounded Haiku fact packet and separate Codex proof design/review; those development calls are not scored trials.

Exactly three fresh public historical behavioral slices are selected: PR20 model precedence, PR23 reasoning propagation and PR37 queued wrap-up notifications. None was previously replayed in this evaluation. Each base fails, its public reference head passes, and an equivalent representation passes the independent owner checks. Freshness is task identity, not temporal novelty or unfamiliar mechanisms. Prompts, boundaries, source pins and runtime hashes are in [discovery registration](DISCOVERY-REGISTRATION.json).

Each task receives one actual Haiku 5.5 discovery call, empty tools, 120 seconds and a USD0.6 CLI guard. Exact quoted source is checked before use; interpretations are discarded. The resulting common packet is shared across original0.6 and revised0.8.1 guidance. The received bytes are then bound in a second registration committed before the six implementation trials. Failed discovery is retained; do not silently substitute models or invent facts.

Each assigned task/arm has one controlled full loop: Opus 5.5 high development (480 seconds/USD4), a fresh read-only Codex check requesting `gpt-6-astra` medium (180 seconds), then one Opus repair or verification stage (300 seconds/USD3). A common 1100-second cell deadline clamps execution and grading. CLI guards/usage are not actual subscription charges. Codex's actual model may be unobserved; requested-only attribution stays explicit. Same models, source, budget, checked discovery and scheduling apply to both arms; only the full guidance tree changes. Common executable/assets are current0.8.1, so this is not a complete old-runtime comparison.

Owner acceptance and reviewer witnesses execute candidate production over immutable baseline tests/dependencies. Solvers see public behavior requirements and baseline code/tests; no accepted solution, history or owner-oracle source. Both arms receive identical executed fixed acceptance diagnostics as repair feedback. Final acceptance reuses those fixed checks and is therefore not an unseen post-repair holdout. The reviewer receives normalized candidate source, diff and diagnostics with policy labels withheld by construction; this is not a claim of perfect style anonymity.

The primary metric is qualified completed final product delivery divided by all three assigned tasks per arm. Report first-pass product grades separately, actual code repairs versus no-change closure, unresolved review findings, timeouts and unknowns. A blocking reviewer finding requires an executable failing witness on the first production and passing witness on final production; missing or always-passing witnesses remain unresolved. A provenance-qualified main timeout can recover through the fixed repair stage; its first outcome remains unknown. Missing/mismatched model, tools, source or lifecycle cannot be repaired into provenance. No started identity is retried or substituted; retain all six assigned identities.

This tests the actual staged discovery/develop/check/repair/recheck lifecycle. It does not certify complete Critical releases, unconstrained autonomous orchestration, representative model quality, improved intake or savings. The task prompts already settle consequential requirements; no scripted interview runs in this cohort. The separate answer-delivery correction tests two observed prior question wordings and four adjacent negatives, preserves the old frozen interviews, and remains a lexical simulator rather than a semantic judge.

The candidate stays experimental and is not installed during this comparison. Keep unfavorable and unknown outcomes, exact first/final patches, independent checks and custody evidence. Do not alter the policies or graders after observing scored outcomes; publish limitations and do not turn CI or model agreement into an accuracy claim.
