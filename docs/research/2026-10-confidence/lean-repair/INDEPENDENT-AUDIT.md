## Remaining-field interpretation

Every closure sets `complete=true` while retaining nonempty `remaining`. The registered acceptance rule requires the latter to be empty, so the four fully bound cells remain nonaccepted. The entries mix prohibited live-provider checks, possible external argument/parser limits, full-suite sandbox limitations, out-of-scope documentation and explanations of intended behavior. They are not all demonstrated failures of the selected product assertions.

This exposes a measurement limitation: a single free-form `remaining` list carries both actual unfinished requirements and disclosed boundaries/limits, while the registered gate treats any entry as failure. The developer prompts ask for truthful remaining gaps without explicitly separating scoped task closure from forbidden live verification or optional limits. Preserve the metric; do not retroactively clear or reinterpret entries to manufacture acceptance. A future design can resolve that distinction before registration. Passing fixtures cannot close an actually required external boundary merely because its disclosure was inconvenient.

The actual closure prompt contains neither `scope_violations` nor `README.md`; controller feedback discloses checks and frozen grade while omitting its recorded source-scope verdict. The review packet's production diff also omits the excluded README edit, although the normalized checkout retains it and the task still states the allowed path.

This makes the repair loop an incomplete channel for controller-detected defects. It does not prove that the missing feedback alone caused the retained edit: the developer already knew the accepted scope and had its current checkout. Also, registered acceptance requires **first** scope clean, so even a later scope correction could not recover that primary result. Any optional scope correction must be a separately registered diagnostic, keep the original rejection intact, and add no success to this six-cell cohort.

## Claim and publication limits

The post-outcome exporter is supplemental and unregistered for outcome selection. Its inspected source keeps frozen analyzer errors, separates behavioral pass from strict delivery, uses exact production patches plus separate excluded-scope diffs, and redirects analyzer output into its own post-analysis directory. Its full launch reconstruction is additional custody evidence, not a new acceptance metric. Exact public patch copying refuses detected private paths or credential-like bytes; this limited pattern scan is not a general privacy guarantee. Final publication still needs inspection of the actual exported files.

`closed-cell-audit.json` contains private detailed bindings and partial evidence. `RESULTS.audit.public.json` is an inspected metadata projection with bounded terminal excerpts and no raw transcripts, session IDs, private paths or authentication. It carries exact source/closure/audit digests and the unknown counts. The cohort supports a small feasibility observation only: selected behaviors passed, strict closure and artifact custody did not establish accepted deliveries. It supports no universal statistical ranking, measured repair gain, or source installation/promotion.
