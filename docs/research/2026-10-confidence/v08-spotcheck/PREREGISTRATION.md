# Small prospective 0.8 versus original-guidance check

Registered 2026-10-13, before model attempts. This is a targeted diagnostic pilot, not a general accuracy benchmark or a release promotion criterion.

- Eight implementation attempts: historical public Tweed PR32 (coordinator event routing) and PR40 (disabled budget/resume), original 0.6 versus 0.8 guidance, two fresh repeats per task/policy.
- Both arms use exact requested Opus 5.5, medium effort, the same current 0.8 executable/assets, native Claude Code 2.1.285, controlled tools, source fixtures and owner oracles. Only the full guidance package differs. This is not a comparison of every old/new runtime capability.
- The existing confined runner, local transport qualification, exact live model/tool/terminal qualification, process cleanup, selected held-out grader and scripted intake are reused unchanged. The new wrapper selects a smaller roster and seals inputs. Peer delegation and external components are unavailable in both implementation arms; this does not test the full Opus/Haiku/Codex workflow.
- Each implementation has 240 seconds and a USD 2 CLI guard for its inference stage. Offline preparation/qualification and owner grading are outside that stage. No started identity is retried or substituted.
- Four scripted clarification episodes: notification ownership and resume precedence under both policies, one episode per case/policy, maximum three rounds. Each round has 120 seconds and a USD 0.6 guard. Facts are supplied; only frozen keyword-recognized questions receive scripted answers. Independent semantic review is separate from that imperfect answer mechanism.

The independent preflight found an interrupted-run aggregation defect: the wrapper could return a short preserved-started status instead of reconstructing saved results. It was corrected before inference. The original preparation seal remains retained, and the replacement seal explicitly binds the old baseline to its original study inventory. Base/head selected-oracle controls and an equivalent PR40 representation control all passed before inference.

## Limits

The two tasks were chosen because the prior prompt bundle lost on them. They are familiar historical tasks, not a representative or fresh held-out sample; targeted improvement may reflect task-specific learning. Equal effort labels do not establish equal compute. The selected tests do not cover every requirement. Interviews measure bounded question/answer/readiness behavior, not live-user satisfaction, source discovery or answer-dependent code implementation. A small win would support further use and investigation, not prove universal superiority, lower cost or uninterrupted autonomy.
