# Smaller models in normal Confidence Protocol use

Research and qualification date: 2026-10-12. The shipped skill now makes qualified
lower-cost workers part of normal substantial-task execution. This is an instruction
policy used through native delegation or an authorized external harness; the proof
CLI does not select or launch models.

## The policy that ships

The core skill invokes [model routing](../../../../skills/confidence-protocol/references/model-routing.md)
for separable discovery, code maps, test proposals and evidence extraction. Complex
task and harness references invoke the same policy. Quick work stays direct when
delegation overhead exceeds its value. Implementation slices have explicit ownership;
consequential ambiguity, reconciliation and final proof require suitable owners and
reviewers. Smaller models assist required Critical reviewers rather than replace
their roles. New Critical software contracts use pinned review records; historical
contracts retain their compatible gates and provenance limitations.

Useful depth comes from bounded independent questions, rather than copies of the
entire task transcript. Owners verify promoted findings against source or actual
checks. Completeness claims need a stated search scope and an independently repeated
search: checking positive citations alone cannot detect a missed writer or caller.
Captures happen on a stable integrated tree, since another worker's edit can stale
whole-inventory source binding. Prior routing qualification can be reused when its
model, runtime, tools, task class and limitations still apply.

Routing considers the whole cost of a verified useful outcome, including context,
startup, checking and repair. Excessive owner repair triggers a different route or
direct ownership. Owner-selected routes can fall back with a recorded reason;
required user models remain requirements, and registered experiments follow their
sealed fallback rule. Native delegation remains within task authority; separately
billed or cross-provider calls remain within granted cost and source authorization.

[Public results](results.json) retain individual labels, evidence pointers, input and

Haiku request finished with exit0, no timeout, an intact structured terminal and
observed model metadata. It had no operational tools and an empty isolated cwd;
native workers were confined by instructions, so mechanical filesystem confinement
is not claimed for them. Process cleanup covers the original group, not detached
descendants.

The owner checked each explicit claim separately from JSON shape and pointer
existence. Five verifier counterexamples reject duplicated or omitted cases,
invented pointers, malformed labels, and a well-shaped incorrect label. This does
not prove that a pointer substantively supports every possible claim. In particular,
the healthy-workflow case claims assigned-stage closure, not semantic software
correctness; a legitimate intermediate incomplete declaration does not invalidate
later completed required peers and final repair.

All three label sets match in this small packet. There is no task-accuracy ranking,
matched cost comparison, representative holdout, or statistical efficacy claim.
One result-informed synthetic extraction request cannot qualify a model for broad
implementation, required review or autonomous closure.

## Actual support work on this policy

Luna also mapped the real shipped references and release declarations. The owner
inspected its cited source and confirmed a concrete gap: `check_release.py` did not
require the new routing reference. The required-file set now includes it, and release
verification checks the archived bytes. That is a useful finding from bounded cheap
discovery, followed by owner verification and a normal source change.

Terra proposed eight normal-use scenarios covering Quick overhead, bounded test
design, consequential ambiguity, Critical roles, unavailable models/tools, unknown
cost, unsupported worker assertions, and shared/dependent edits. The owner checked
those proposals against policy. They are scenario proposals, not executed regression
tests; its `policy_satisfied=false` cases identify unresolved task proof, rather than
showing that the policy would permit false closure.

Two fresh-context Opus5.5 reviews challenged the policy. Their supported findings
led to reusable qualification, negative-search verification, explicit authority and
fallback rules, stable integrated proof captures, repair-overhead escalation, and
read-only metadata reporting. Review prose does not prove dispatch behavior. The
reviewer's suggested breaking requirement for all legacy Critical reports was not
adopted: new authoring guidance uses pinned records while legacy gates remain
compatible. Requested-only model identity stays explicit when actual identity is
unobserved; invented runtime identity is never required to make a record pass.
[Review receipts and owner resolutions](policy-review.json) preserve the scope,
original source hashes, remaining mechanical limits and post-review edits; revised
source is not relabeled as the reviewer-observed version.

An independent forward test used the skill on the actual release-inclusion task in
an isolated copy. It selected direct deterministic work because another model would
duplicate this bounded enumeration. The real release checker accepted a healthy
Git archive and rejected an archive that export-ignored only `model-routing.md`,
even though that source file remained present. The owner independently rechecked
both archive bytes through the validator at commit5848a69. Copied skill/validator
hashes matched that source at the owner check; later validator changes have their
own separately reviewed proof below. Its local strengthened fixture passed nine tests and

## Cost observability surprise

The Haiku CLI reported6.516s and a nonzero cost estimate of$0.049772, but its model
usage record says `costBasis: unknown`. It reported2 ordinary input tokens,2728
one-hour cache-creation tokens and1397 output tokens;901 thinking tokens are part
of that output, so adding them again would double-count. Native Luna/Terra worker
usage and dollar telemetry are unavailable and remain null.

An illustrative API calculation using the documented short-context global Standard
rates gives `(2 ×0.10 +2728 ×0.20 +1397 ×0.50) /1e6 = $0.0012443`. This assumes
the returned components are billed under those API rates; it is neither a corrected
CLI invoice nor subscription billing. The CLI estimate is40times that calculation.
We have not inspected the estimator implementation and cannot establish the cause.
Keep the CLI estimate and unknown basis rather than choosing whichever price looks
cheaper. [Haiku input, cache-write and output rates](https://platform.claude.com/docs/en/models/haiku-5-5/overview).

The runtime usage catalog also returned a200k context window where the current
public model specification says1M. This does not establish either a successful1M
request or an actual server200k limit: catalog metadata and exercised capacity are
different evidence. No large-context boundary was tested here.

## Relationship to the real PR experiments

The original84-assignment seven-arm study, invalid V148 block and qualified V248
block retain their frozen models and CP package. V2 uses the package at9f3afa,
before this model-routing policy addition. Its outcomes therefore cannot measure
the effectiveness of the new small-model policy. None of this pilot is pooled into
the historical PR denominators. A future efficacy test should compare the actual
routed workflow against direct ownership on representative tasks, include owner
verification/repair effort, preserve missing costs, and assess final behavioral
correctness and proof closure separately.
