# Required archive resource type proof

The reviewed release validator satisfies the bounded contract: all nine required named resources must be regular tar members (`TarInfo.isfile()`), ordinary directory entries remain valid, and archived Python is inspected without execution. The accompanying [machine-readable proof](RELEASE-TYPE-PROOF.json) preserves source, receipt, log, harness and archive hashes.

A separate preimplementation proof designer found that only the manifest and diagnostics resource were type-checked. Seven other required resources could be directories, links or FIFO members. The actual RED run of the expanded seven-test suite recorded **28 failures**, followed by a **seven-test GREEN** run after the uniform required-member gate. Both logs were checked against their receipt hashes. The preserved earlier baseline includes the six-test file before the extra regression test was added.

The postimplementation reviewer was a separate actor who did not implement the patch. The reviewer read the source, earlier proof design and logs, then ran **97 isolated controls; all passed**, plus the copied seven-test suite. Controls used an independent literal list of the nine resources. Each resource rejected directory, symlink, hardlink, FIFO, character-device, block-device and unknown member types: 63 cases. Another 18 valid-target link cases also rejected. Healthy archives, normal directories, missing resources, a future required resource and repository-only resources were checked. Two deliberately weak mutations were caught: checking only model-routing.md accepted a README symlink, while rejecting every nonregular member refused a healthy archive containing ordinary directories.

The historical real `git archive` at HEAD `c34d330a0c194cb49a88a2b8e533d65401d8e765` passed with **26 entries, including seven directories**. Both archived Python resources also carried filesystem-write and raising side effects; healthy fixture archives passed without creating the execution marker. The checker and test source hashes remained unchanged throughout the review and match the hashes at public proof creation.

These are separate designer and reviewer observations, with shared repository and parent context. They do not establish blind review, model diversity or authenticated identity. Receipt start/end workspace hashes bind endpoints, not every event between them; the earlier RED workspace was not reconstructed. Individual preserved baseline and current source hashes are reported separately. Raw private paths and logs are omitted.

No actionable findings remained. The production suite lacks an explicit normal-directory positive test and derives its resource list from production `REQUIRED`; the independent controls cover those gaps for this reviewed source. This proof does not establish general tar security, exhaustive malformed/archive-format behavior, a published release, live benchmark results or Confidence Protocol efficacy.
